# AGENTS.md — PunishNotify

Инструкции для нейросети (ассистента), работающего с репозиторием PunishNotify.

## Обязательные правила

### Коммиты и пуши

1. **После ЛЮБОГО изменения кода** (новая фича, багфикс, рефакторинг, настройки, доки)
   ты **ОБЯЗАН** закоммитить изменения и запушить их в GitHub.
2. Не оставляй незакоммиченные изменения. Рабочее дерево должно быть чистым
   (`git status` — чисто) после завершения каждой задачи.
3. Коммиты пиши по-русски, кратко и по делу: `git add -A && git commit -m "..."`.
4. Пуши сразу после коммита: `git push`.
5. Пушь в ветку `main` (в репозитории одна основная ветка).
6. Если локальные изменения конфликтуют с удалёнными — сначала сделай
   `git pull --rebase`, затем снова пушь.

### Сборка

7. Сборка плагина: `./gradlew build` (артефакт лежит в `build/libs/PunishNotify.jar`).

### Релизы

8. **Когда задача требует выкладки новой версии плагина** (пользователь просит
   «сделай релиз», «зарелизь», «выложи версию» и т.п.) — создай Git-тег
   `v<версия>` по схеме `vMAJOR.MINOR.PATCH` (например `v1.1.0`), затем запуши тег.
9. Пуш тега запускает GitHub Actions workflow `.github/workflows/release.yml`,
   который сам соберёт плагин и создаст GitHub Release с файлом `PunishNotify.jar`.
10. Проверь после пуша тега, что релиз создан: `gh release view v<версия>`.
11. Версия в `build.gradle.kts` (`version`) и в `src/main/resources/plugin.yml`
    должна совпадать с тегом релиза. При выпуске релиза — обнови обе, закоммить,
    запушь, а только потом ставь тег.

### Обновление сервера после релиза

12. **После каждого релиза ты ОБЯЗАН** скопировать свежий собранный плагин
    `build/libs/PunishNotify.jar` в папку сервера:
    `C:\Minecraft\Paper-1.21.11\plugins\PunishNotify.jar` (перезаписать старый файл).
13. Затем в репозитории сервера `C:\Minecraft\Paper-1.21.11` закоммить это
    изменение и запушить в репу сервера (`git add -A && git commit -m "..."
    && git push`). Пушь в основную ветку этого репозитория.
14. Если после обновления сервер нужно перезапустить — действуй по инструкциям
    из AGENTS.md сервера (в `C:\Minecraft\Paper-1.21.11` / на VPS через `./mcs.sh`).

### README

15. **Каждый раз при добавлении новых механик, команд или пермишеннов** —
    актуализируй `README.md` в этом репозитории, закоммить и запушь обновление вместе
    с изменениями кода.

## Порядок действий для релиза (чек-лист)

1. Обнови версию в `build.gradle.kts` и `plugin.yml`.
2. Актуализируй `README.md` (новые механики/команды/пермишенны).
3. `git add -A && git commit -m "..." && git push`.
4. `git tag vX.Y.Z && git push origin vX.Y.Z`.
5. Дождись завершения workflow: `gh run watch`.
6. Убедись, что релиз создан: `gh release view vX.Y.Z`.
7. Скопируй `build/libs/PunishNotify.jar` в `C:\Minecraft\Paper-1.21.11\plugins\`,
   закоммить и запушь в репозиторий сервера.

## Важно

- Никогда не коммить: `build/`, `bin/`, `.gradle/`, `.classpath`, `.project`,
  `.settings/`, `logs/` (см. `.gitignore`).
- Не пушить с `--force`, не переписывать историю.
- Все изменения вноси сначала локально, собирай и проверяй локально, затем
  коммить/пушь/релизь.
